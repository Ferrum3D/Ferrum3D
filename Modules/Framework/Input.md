# Input

`FeFramework` exposes input under `FE::Input`. `Core::Backend` enumerates devices and supplies held, pressed, and released state. `Desktop::Backend` translates `PlatformApplication` events once per world update. Repeated key-down events do not generate new presses. Focus loss releases held keys and buttons; mouse position is re-established after focus/leave transitions to avoid jumps.

Register `Framework::WorldTimeService` before `Input::WorldInputService`. Poll platform events before `EntityWorld::BeginUpdate()`. The input service snapshots devices during its service update and resolves a caller-owned `MappingStack` with that frame's elapsed time. A custom backend can be installed with `SetBackend`.

`Action` and `MappingTable` are ordinary source-less serialized assets. Authored components reference them through `IO::Link`. Mapping tables have one mapping per action, with keyboard vector contributions and mouse button, motion-axis, or wheel contributions. `kSum` sums contributions, `kAny` selects the first active contribution, and `kAll` requires every binding. `kNormalizeDirection` clamps vector length to one. An optional mouse-button gate supports combinations such as RMB + mouse motion.

Push tables in ascending priority. Tables default to disabled; pass `MappingStackFlags::kEnabled` or call `Enable`. The highest enabled table owns a duplicate action even when its bindings are inactive. A consuming action reserves its active physical controls from lower tables, while mappings within the same table can share controls. Handles do not acquire residency: retain an asset request or use component hard dependencies.

`Resolve` returns action IDs, types, values, active state, and optional state events. A null processor emits `kFinished` once for a press. `ContinuousActionProcessor` emits Started, InProgress, and Finished on release. `HoldDurationActionProcessor` emits Started/InProgress while waiting, Finished once at the threshold, or Canceled on early release. Runtime timing belongs to the stack, so two stacks using the same asset are independent. Disabled/removed actions cancel pending work, and asset-generation or table-owner changes reset processor state. Resolution is cached by frame number; table edits take effect on the next frame. `Clear` immediately drops all state.

`Rc<T>` serialization stores `m_typeId` and `m_value`, like `Rtti::Any`, without modifying `Rc`. The complete registered dynamic object must be default constructible and serializable. Deserialization constructs through RTTI, adjusts the base address, and commits the new reference only after successful loading. Unregistered dynamic types and non-default-constructible objects assert. This is inline value serialization: shared pointer identity and cycles are not preserved.
