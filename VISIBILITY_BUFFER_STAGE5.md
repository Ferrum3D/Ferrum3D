# Stage 5: default visibility/deferred pipeline

RendererSample, GameSample and GpuDrivenTestApp install `Visibility::ViewModule`, `SurfaceEvaluation::ViewModule` and `DeferredShading::ViewModule`. Each stage takes only the frame graph and blackboard. Visibility publishes its coverage target; evaluation publishes the four GBuffer targets; shading consumes that output. The renderer publishes common `ViewData` camera constants and scene-owned `SceneData` registries before object modules prepare their view inputs.

Render targets and classification buffers are created as logical resources for each graph. The graph infers usage, commits memory through its pool, tracks dependencies and retires submitted resources. There are no cached-target or cached-classification `Ensure` functions, explicit target/classification commits, shared-scratch coordination between passes, or scratch-byte accounting. Evaluation and shading have independent graph resources, so the old shared-scratch footprint figures no longer describe the implementation.

Common shader `ViewData` contains camera matrices, camera position, viewport and background. `MeshViewData` adds per-view mesh draw/culling data and a descriptor for `MeshSceneData`. Mesh tables and the producer's visibility namespace are uploaded once per scene after database uploads establish table addresses. Nested descriptors require an explicit scene-buffer read declaration; geometry device-address reads also retain their explicit graph declarations.

Object modules publish `SurfaceEvaluationBatch` entries containing local binding IDs, opaque reconstruction data and classifier/debug pipelines. The generic visibility and evaluation stages do not inspect mesh modules or tables. Evaluation clears coverage once, classifies each nonempty producer batch and dispatches only its registered evaluation shaders. Deferred shading classifies the resulting GBuffer routes using the scene's independent shading registry. The built-in material shading implementations live under `Shaders/Materials`.

The visibility word reserves four bits for a scene-assigned producer namespace, leaving 28 bits for the producer's local instance ID, with zero reserved for background. The current contract supports 16 simultaneous producer namespaces and 268,435,454 as the largest local instance row. Namespaces are reused when modules are destroyed. Object-specific classifiers and reconstruction reject foreign namespaces; additional opaque object types supply their own producer shaders without changing the generic passes.

Default rendering executes all three stages. The old forward mode, passes, material techniques, shaders and draw tags are removed. `--visibility-debug` selects visibility/reconstruction and GBuffer views or deferred rendering. Unsupported surface/shading combinations remain magenta. Registries reference-count registrations and reuse vacant shader slots after reload, stream-out and destruction. Dirty database-page synchronization remains unchanged.

RDNA2+ and Turing+ are the baseline. HDR is B10G11R11_UFLOAT, depth is D32_SFLOAT, visibility is R32G32_UINT and each GBuffer plane is R32_UINT. Wave-size selection remains the only relevant capability check.

## Validation

The GPU probes retain coverage for classification, GBuffer codecs, deferred lighting, indirect arguments, shader registry lifetime, and reconstruction. Scratch-accounting and shared-storage tests were removed along with that implementation. The raster probe now uses a nonzero producer namespace to verify coverage encoding, classification and reconstruction together. It also uses a nonsymmetric projection and the material evaluation view loader to verify reconstructed UVs, gradients and depth against rasterization. Object data remains opaque in generic passes; mesh shaders reinterpret its descriptor as a structured MeshViewData buffer to preserve matrix layout.

The refactor passes configure.bat, reflection generation and Debug builds of both samples, the GPU stress app and the relevant test executables. All seven graphics tests pass with GPU-assisted validation; all 24 GameFramework tests and the standalone reflection-link check pass. Both samples pass default-rendering smoke runs with API validation. GameSample also passes normal reconstruction, evaluation-group and surface-normal debug smoke runs. The 15-frame GPU flight stress run passes GPU-assisted validation across two views, resize, reload, module activation changes and empty scenes, without validation errors. Material depots were rebuilt manually through FerrumCli.

GPU marker scopes distinguish DepthVisibility, SurfaceEvaluation/SurfaceClassification and DeferredShading/ShadingClassification. Per-stage GPU timing and physical VRAM residency require profiler measurements; the previous shared-scratch byte counts and frame-timer figures are not current measurements.
